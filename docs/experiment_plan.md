# 实验设计与答辩指标

## 实验目的

验证可控解题提示生成机制在教育辅导场景中的有效性，重点关注两个问题：

- 系统是否能够降低答案泄露风险。
- 系统是否仍能保持提示的启发性、针对性和学习帮助度。

## 对照设置

建议设置三组对照：

1. 直接回答组：模型不加答案泄露约束，直接回应学生请求。
2. 普通提示组：只使用基础 System Prompt，要求模型不要给答案。
3. 可控提示组：使用本系统的“私有提示计划 + 学生提示生成 + 泄露检测 + 自动重写 + 强度控制”链路。

## 定量指标

- 答案泄露率：`is_leaking_answer = 1` 的提示数量 / 总提示数量。
- 平均泄露评分：所有提示的 `leakage_score` 平均值。
- 自动重写触发率：`rewrite_count > 0` 的提示数量 / 总提示数量。
- 平均重写次数：所有提示的 `rewrite_count` 平均值。
- 不同提示强度下的泄露风险：按 `hint_strength` 分组比较泄露评分和重写率。
- 不同教学意图下的使用偏好：按 `pedagogical_intent` 统计学生最常请求的辅导类型。
- 提示后正确率：学生接受提示后再次作答正确的比例，可作为后续扩展指标。

## 人工评价指标

可邀请教师或同学对抽样提示进行 1 到 5 分评价：

- 启发性：提示是否能引导学生思考。
- 非泄露性：提示是否避免直接给出答案、选项或关键结论。
- 针对性：提示是否贴合学生当前错误或请求。
- 表达清晰度：语言是否简洁、自然、容易理解。

## 数据来源

系统中的 `interaction_logs` 表可直接提供实验数据：

- `user_query`：学生请求原文。
- `ai_response`：系统生成的受控提示。
- `is_leaking_answer`：最终提示是否仍被判定为泄露。
- `leakage_score`：泄露评分。
- `rewrite_count`：自动重写次数。
- `leakage_reason`：泄露检测原因。
- `hint_strength`：提示强度，包含轻提示、中提示、强提示。
- `pedagogical_intent`：教学意图，包含概念提示、错因诊断、下一步引导、知识点复习、自主提问等。
- `hint_safety_status`：安全状态，包含泄露检测通过、已自动重写、保底安全提示等。
- `created_at`：交互时间。

`study_sessions` 表可用于学习时长分析，`login_logs` 表可用于系统活跃度分析。

## 答辩展示顺序

1. 展示研究背景：LLM 辅导容易给出答案，削弱学生独立思考。
2. 展示系统原型：学生测验、错题复盘、请求智能辅导、个人学情报告。
3. 展示可控链路：提示强度控制、私有提示计划、答案隔离、泄露检测、自动重写。
4. 展示管理端实验看板：泄露率、重写率、提示强度分布、教学意图分布、实验数据导出。
5. 展示实验方案：三组对照、定量指标和人工评价指标。
6. 总结创新点：将提示生成从单次 Prompt 约束扩展为可观测、可重写、可量化的闭环系统。

## 论文表述建议

可以将系统贡献概括为：

- 构建了面向教育解题场景的可控提示生成原型系统。
- 设计了多阶段推理控制链路，降低标准答案直接进入学生可见输出的风险。
- 引入提示强度控制与教学意图记录，使提示生成过程具备可调节性和可分析性。
- 引入答案泄露检测与自动重写策略，使生成过程具备可观测性和可干预性。
- 建立了结合系统日志、统计看板与人工评价的实验评估框架。
