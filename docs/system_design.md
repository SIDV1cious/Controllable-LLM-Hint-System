# 系统设计说明

## 研究目标

本系统围绕“可控解题提示生成”展开，重点解决大语言模型在教育辅导场景中容易暴露最终答案、关键数值或完整解法的问题。系统不是简单阻止模型回答，而是在保持启发性的前提下，通过生成控制、内容检测和动态重写降低答案泄露风险。

## 总体架构

系统采用 Streamlit + MySQL + LLM API 的轻量级 Web 架构。

- 表现层：`app.py` 提供学生端和管理员端页面。
- 数据层：MySQL 存储用户、题库、学习时长、作答记录和辅导交互日志。
- 模型层：DeepSeek Chat 兼容 OpenAI SDK，用于自动判题、提示计划、学生提示生成、泄露检测与重写。
- 公式输入层：`streamlit-component-x` 使用 React 与 MathLive 实现 LaTeX 输入。

## 学生端流程

1. 学生选择课程并进入测验。
2. 系统从数据库随机抽取 10 道题。
3. 学生提交答案后，系统使用判题 Prompt 对照标准答案与解析进行 PASS/FAIL 判断。
4. 学生在结果页对错题发起智能辅导请求。
5. 系统生成受控提示，并将交互写入日志。
6. 学生可在个人学情中心查看累计学习时间、正确率和错题辅导记录。

## 管理端流程

管理员可以查看：

- 最近 7 天活跃用户趋势。
- 各课程学习时长占比。
- 各课程平均正确率。
- 智能辅导答案泄露控制统计。
- 登录日志、学习时长记录和 AI 辅导交互记录。
- 课程和题库的增删改查。
- 全局系统 Prompt 热更新。

## 可控生成机制

系统当前实现的是推理阶段控制链路。

### 1. 私有提示计划

系统先让模型读取题目、标准答案、标准解析、学生答案和学生请求，生成不会展示给学生的安全提示计划。计划中包含知识点、错误诊断、下一步提示目标、允许提示层级和禁止出现的答案相关内容。

### 2. 答案隔离生成

学生可见提示生成阶段不再直接传入完整标准答案和标准解析，而是传入题目、学生答案、判题结果、学生请求和私有提示计划。这样可以降低模型在最终输出中复制标准解析或直接给出答案的概率。

### 3. 泄露检测

候选提示生成后，系统使用独立的泄露检测 Prompt 对其进行评估。检测维度包括：

- 是否直接给出最终答案或选择题选项。
- 是否暴露关键数值或最终表达式。
- 是否给出完整解法。
- 是否给出决定答案的关键中间结果。
- 是否通过确认/否定学生答案间接泄露答案。

检测输出包括 `is_leaking`、`score` 和 `reason`。其中 `score` 取值为 0 到 3。

### 4. 自动重写

当检测结果显示存在泄露风险时，系统调用重写 Prompt，要求模型保留启发性但移除答案泄露内容。系统最多重写两次，并再次检测重写结果。

### 5. 日志与指标

每次辅导会记录：

- `is_leaking_answer`：最终提示是否仍被判定为泄露。
- `leakage_score`：泄露评分。
- `rewrite_count`：自动重写次数。
- `leakage_reason`：检测原因。

这些字段可以直接用于论文实验中的泄露率、控制成功率和重写代价分析。

## 当前边界

当前系统主要实现推理阶段控制，尚未进行模型微调、对比学习或偏好优化。论文中可以将其定位为“基于多阶段推理约束与检测重写的可控提示生成原型系统”，后续扩展方向包括人工标注数据集、偏好优化训练和更细粒度的提示等级控制。

## 工程实现优化

为保证毕业设计答辩演示时的稳定性，系统在工程层面加入了以下优化：

- 大模型调用参数集中配置，支持通过环境变量调整模型名、超时时间、最大重试次数、阅卷并发数和重写次数。
- 阅卷阶段使用异步并发，但通过 `ASSESS_CONCURRENCY` 限流，避免一次提交多题时 API 请求过载。
- 抽题阶段避免 `ORDER BY RAND()`，先查询课程题目 ID，再在应用层随机抽取指定数量题目，提升大题库场景下的响应速度。
- 泄露指标字段迁移使用进程级缓存，避免每次写入交互日志都重复执行表结构自检。
- 学生结果页默认展示首道错题，并提供本次测验结果导出，方便教师查看演示闭环。
